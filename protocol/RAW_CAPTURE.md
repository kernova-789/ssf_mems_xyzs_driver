# 连续原始 XYZ 与特征交替采集

驱动启动后先匹配串口、确认采样配置并读取一份特征，然后进入交替流程：
默认特征轮询约 5 秒、连续原始 XYZ 约 5 秒，重复运行。FFT 不在驱动中计算。
`probe` 本身不发送 Modbus；所有业务通信仍在后台采集线程中执行。
普通通信的目标波特率来自设备树 `current-speed`，未配置或不可用时为 9600。
这不改变原始模式临时使用 1000000 baud、结束后恢复普通通信速率的流程。

## 采集时段

设备树可选属性如下，缺失、读取失败或范围非法时日志提示并采用 5000 ms：

```dts
sange-cbm,raw-duration-ms = <5000>;
sange-cbm,feature-duration-ms = <5000>;
```

时长范围为 100～60000 ms，`raw-duration-ms = <0>` 表示仅采集特征。
原始时段从接收到首个 CRC 正确的数据包开始计时；首包最多等待 15 秒。
这是固件完成当前特征计算的预算，不表示收到启动命令后立即开始采集。
收流期间连续 1 秒没有正确数据包，会退出并尝试恢复通信。
特征时段按轮询边界切换，可能多出一个轮询间隔；串口切换、首包等待、
停止排空及恢复验证时间不计入这两个时段，因此并非严格每 10 秒一个周期。

## 固件控制流程

1. 在配置速率下读取 `40052`，确认采样率索引为 0～8。
2. 发 `0x03` 读取 `40058`（线上地址 `0x0039`，数量 1）。没有普通读应答。
3. 主机立即切到 1000000 baud；固件结束当前任务后还会等待 150 ms 再切速。
4. 接收固定 392 字节私有包：`15 + BE32 包号 + 64 × XYZ × BE16 + CRC16 + 17`。
   CRC 校验覆盖前 389 字节，线上 CRC 低字节在前。没有 Modbus 从站地址或字节计数。
5. 原始时段结束，停止向 IIO 发布；仍解析排空中的数据。
6. 在 1000000 baud 下用 `0x06` 写 `40059=1`（线上地址 `0x003a`）。
   已见过私有包时，发送前最多等待 300 ms，尽量在下一完整包结束后发送，
   减少 RS485 半双工碰撞；非实时调度不能保证命中空档，仍需重试和验证。
7. 保持 1 Mbaud 接收，观察至少 300 ms 无接收活动；单次观察最多 1000 ms。
   仍有输出时重发停止，不在数据流仍持续时直接切速。
8. 主机恢复普通配置速率、清理残留字节，读取 `40102` 并再次确认安静窗口。
   停止应答可能被固件原始包发送覆盖，不能依赖它。
   一轮恢复最多六次停止尝试；失败保留“恢复未确认”状态，后台退避后优先
   重试停止，禁止普通读写或将临时 1 Mbaud 当作配置变化写入 Flash。

整个过程持有 `protocol.bus_lock`，不会夹入普通 Modbus 请求。
采集线程同时持采集锁，串口相关的 sysfs 操作可能等待本轮原始采集结束。
卸载会唤醒原始采集等待，停止并通过专用只读请求确认普通通信，再注销 IIO。
普通请求关闭状态不会因此重新开放。首包前卸载时，必须先等有效私有包或
原启动期限结束，避免“停止命令发得太早，随后固件才启动”的遗留流。
清理是有界尝试，串口故障时会记录未确认状态，而不是保证硬件必然停止。
即使线程已经因停止失败进入退避，线程退出后也会再检查和清理未确认的私有流。
启停连续模式不写 `40102`、`40103`、`40110`，不会为每轮切换反复写 Flash。

加载时如果扫描到 1 Mbaud，先被动观察 400 ms：发现有效私有包就先停流，
然后只读确认普通配置速率；若未知，停止且观察到安静后才做只读扫描。
读取 40102 得到较低配置而当前通信为 1 Mbaud 时，也先停流，不覆盖普通配置。

固件连续模式强制 8N1，退出时也只恢复无校验。因此奇/偶校验配置不进入
原始模式，而是记录提示并继续特征采集。索引 9 的采样率也不进入连续模式。
默认采样率索引 6（5333.4 Hz）可以使用此功能；时间基准以传感器实际时钟为准。

## 两个 IIO 设备

- `ssf_mems_xyzs`：原有特征通道，扫描布局保持不变。
- `ssf_mems_xyzs_raw`：原始 XYZ、包号、包内序号和可选主机接收时间戳。

原始设备的 `scan_elements`：

| 字段 | scan_index | 存储类型 |
| --- | --- | --- |
| `in_accel_x` / `y` / `z` | 0 / 1 / 2 | 本机字节序 s16 |
| `in_count0_packet_sequence` | 3 | 本机字节序 u32 |
| `in_count1_sample_index` | 4 | 本机字节序 u16，0～63 |
| `in_timestamp` | 5 | 本机字节序 s64，ns |

XYZ 保留固件平均降采样后的 ADC 计数，不是特征 RMS，也不去除重力/DC。
`in_accel_*_scale` 为 `0.004788403` m/s²/count（±16 g，16 位有符号）。
时间戳是主机解析/发布样本的时间，不能当作精确等间距的传感器采样时间。
后续计算 FFT 应结合 `raw_sampling_frequency`、包号和包内序号重建序列，
遇到丢包、重复包、切换时段或 IIO 丢样就分段，不能把间断数据拼成连续波形。

原始设备只提供 buffer 采样及 scale，不提供逐通道 `in_accel_*_raw` 快照。
现有 `tools/iio_read` 读取特征 sysfs 缓存，不能用于读取此高速原始流。

在开发板 root shell 中启用并保存原始 buffer 的示例：

```sh
raw_iio_dir=
for candidate in /sys/bus/iio/devices/iio:device*; do
    if [ "$(cat "$candidate/name" 2>/dev/null)" = "ssf_mems_xyzs_raw" ]; then
        raw_iio_dir="$candidate"
        break
    fi
done
test -n "$raw_iio_dir" || exit 1
echo 0 > "$raw_iio_dir/buffer/enable"
for channel in "$raw_iio_dir"/scan_elements/*_en; do
    echo 1 > "$channel"
done
echo 8192 > "$raw_iio_dir/buffer/length"
echo 1 > "$raw_iio_dir/buffer/enable"
dd if="/dev/${raw_iio_dir##*/}" of=raw_capture.bin bs=24 count=4096 iflag=fullblock
echo 0 > "$raw_iio_dir/buffer/enable"
```

全部字段启用时，一条扫描记录在目标平台为 24 字节：XYZ 位于 0/2/4，
包号位于 8，包内序号位于 12，时间戳位于 16，中间填充为零。
实际程序仍应读取 `*_index`、`*_type` 和启用掩码计算布局，不硬编码设备编号。
buffer 未启用时驱动仍按时交替采集，但不保存未消费的历史样本。

原始设备的只读统计：`raw_active`、`raw_packets`、`raw_sequence_gaps`、
`raw_crc_errors`、`raw_buffer_drops`、`raw_sampling_frequency`。
统计在每轮启动时清零；`raw_packets`、`raw_sequence_gaps`、`raw_crc_errors`
只统计有效采集阶段，不再混入停止排空。`raw_crc_errors` 是损坏候选包次数，不是精确丢包数；
`raw_buffer_drops` 统计 buffer 推送失败的样本数。

新增只读诊断属性：

- `raw_drain_packets`、`raw_drain_sequence_gaps`、`raw_drain_crc_errors`：停止/恢复阶段统计，不发布到 IIO。
- `raw_start_wait_ms`：本轮采集线程确认首包所用时间。
- `raw_stop_attempts`：本轮累计停止尝试数，包括后续后台恢复。
- `raw_link_mode`：0=普通通信，1=等待首包，2=原始收流，3=恢复未确认。
- `raw_publishing`：是否处于向 IIO 发布的采集阶段；buffer 未启用时不存储样本。

这些诊断属性按成员读取，不是一份原子快照，观察边界时可能跨越状态切换。

特征在原始模式下不更新，特征缓存会被置为无效；恢复后由普通轮询重新发布。
固件没有特征批次编号/就绪标志，恢复后的首份寄存器结果仍可能是前一批特征，
需要等待固件下一次完成计算才会更新。这不能由 Linux 读取操作强制刷新。

本功能基于固定固件 `samp.c:returnSampDataMode/vTaskAcquisition` 和
`Modbus.c:makeMasterResp_3` 实现。串口吞吐、固件处理延迟和停止可靠性仍需实机验证；
包号连续也不能证明固件内部完全没有过采样丢失，驱动不会对此作保证。

## 已复现的硬件运行边界

2026-10-09 的 RS485 实测曾出现：私有模式仍在 1 Mbaud 应答，40102=3
（普通配置为 9600），停止标志保持 1，却不再输出原始包，也未恢复普通速率。
固定固件 `vTaskAcquisition()` 仅在 `ucProcessedTimes != ulCollectTimes`
时处理停止标志；因此“不再产生待处理采样包”时，单纯重发停止不能保证退出。
这与现场相符，但尚不能据此确定采样停止的根因。

驱动会离线、禁止普通业务并有界重试，不把临时速率保存到 Flash。
首包预算和包间发送避让没有消除这一现象，当前版本仍未通过长稳测试。
在没有可控复位/电源线路的情况下，不能承诺由驱动自动恢复此状态；测试中
传感器断电重启可以恢复。不要使用重复写 40110 保存/重启代替可靠的停流。
