# Modbus 表驱动配置

`modbus_table.h` 是帧格式、寄存器属性和块命令的配置入口：

- `ssf_frame_table`：功能码、请求/响应长度和字段位置；组帧与响应拆解共用这些描述，CRC 也共用一套实现。
- `ssf_reg_table`：实际地址、读写权限、响应格式及特征缓存字段映射。
- `ssf_block_cmd_table`：块命令的地址范围、读写方向和解码方式；`sparse_read` 表示可以按保留寄存器拆成连续段读取。

## 不再读取某个特征

从 `ssf_reg_table` 删除对应寄存器的整个初始化项即可，不需要修改 `modbus.c`，也不要重编号剩余寄存器的 `display_reg` 或 `protocol_addr`。

例如删除 40002 后，`ssf_mems_modbus_read_features()` 自动发送两次读取：40001（1 个寄存器）和 40003～40029（27 个寄存器）。不用修改块表中的起点和 `reg_count = 29`，这里仍表示原始地址范围，而非剩余表项数量。响应根据实际请求的起始地址映射，后续字段不会前移；删除项对应的缓存字段每轮成功读取后为零。

连续的保留地址会合并读取；表项顺序不影响读取顺序。全部特征项删除时不发送读取请求，缓存更新为全零。分段读取任何一步失败时，不覆盖上次成功的缓存。

通用 `ssf_mems_modbus_read()` / `ssf_mems_modbus_write_regs()` 不会跳过调用者指定范围内的缺失地址：缺失返回 `-ENOENT`，权限不足返回 `-EACCES`，均不发送请求。固定十参数写入仍要求块内所有寄存器存在且可写，不能通过删表项改变这个固定命令。

## 验证与待处理事项

运行 `python3 tests/protocol/run_tests.py` 可检查删表、分段读取、字段映射、组帧和接收解析。测试使用模拟串口，传感器是否接受任意子范围读取/写入仍需实机验证。

按此前要求，未认领帧仍调用未声明、未定义的 `ssf_mems_protocol_process()`，完整驱动编译会在此报错；本次没有替你决定未认领帧的处理策略。私有原始数据格式也尚未实现，通用读取会明确返回 `-EOPNOTSUPP`。
