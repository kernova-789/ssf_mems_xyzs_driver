# 协议模块与表驱动配置

## 文件职责

- `modbus.c/.h`：无设备状态的帧长度、CRC、请求编码和响应解码，不调用请求、接收或传感器业务。
- `modbus_request.c/.h`：查表校验、发送、请求状态、等待/超时，以及按实际请求上下文认领响应。
- `modbus_receive.c/.h`：FIFO、候选帧和拼帧工作项；只通过初始化注册的回调交出完整帧，不直接调用请求或业务模块。
- `protocol.c/.h`：完整帧分发、特征分段读取、寄存器字段映射、特征缓存、固定工作参数操作及波特率/校验位配置。
- `modbus_types.h`：公共线格式常量、帧/寄存器/块描述和实际请求描述类型，不包含上层模块接口。
- `sensor_data.h`：可复制的传感器结果类型，不含锁或运行状态。
- `modbus_table.h`：实际帧格式、寄存器属性和块命令的唯一配置入口，三个数据表仍保留在这里。

帧数据的处理顺序是：串口字节 → 接收工作项拼帧与 CRC 校验 → 已注册的 `ssf_mems_protocol_handle_frame()` → 请求层认领 → 由 `modbus.c` 按请求描述解码。认领成功后唤醒等待者；未认领帧直接丢弃，不额外解析、不更新请求结果或特征缓存，也不根据长度猜测寄存器起始地址。接收层在回调结束后统一释放帧缓冲区。

接收回调同步执行，帧缓冲区仅在回调期间有效，不能保存其指针。上下文必须存活到接收清理结束；回调不能同步等待需要同一接收工作项处理的新响应。FIFO 拼帧函数已经私有化，外部不能绕过工作项的串行保障。

请求层在每次发送前等待接收空闲（按 3.5 字符时间估算，至少 2 ms），并清空 FIFO
及未完成候选帧。超时、部分发送或等待被信号打断后，下一次发送还需等待隔离窗口：
`max(1000 ms, 上次请求响应超时)`，从上次失败结束时开始计时；隔离期间没有待匹配
请求，旧应答直接丢弃。隔离结束后，空闲检测最多再等待 1000 ms，持续噪声返回
`-ETIMEDOUT`，卸载和信号可以中断等待。两个常量位于 `modbus_request.h`。

RTU 读取应答不携带寄存器地址或事务编号，因此这依赖传感器的最大迟到时间有界。
如果旧应答超过隔离窗口且恰好在新请求之后到达，软件无法仅凭同形应答区分两者；
硬件测试必须测量最大响应延迟并据此增大窗口。错误后的重试和波特率扫描也会因此变慢。

接收层对半帧设置最长 RTU 帧传输时间加 100 ms 的存活预算，使用实际主机波特率
和校验格式计算。空闲定时工作回收残留候选帧，新字节解析时也回收超过绝对寿命的
候选帧，防止长期占满四个槽位。解析、过期清理和 flush 共用 `parse_lock`；停止时
同步取消解析工作及定时工作再释放资源。请求层不得持 `req.lock` 调用 flush，
否则等待接收回调会造成锁互等。

## 模块状态和初始化

`ssf_mems_xyzs_data` 组合设备指针和各模块状态，`probe()` 依次调用各模块初始化函数：

- `protocol` / `ssf_mems_protocol_init()`：特征缓存、缓存互斥量、公共串口总线锁、缓存有效标记及启动参数。
- `modbus_req` / `ssf_mems_modbus_request_init()`：当前请求、请求互斥量和等待队列。
- `modbus_rx` / `ssf_mems_modbus_receive_init(data, handler, context)`：接收 FIFO、自旋锁、解析互斥量、解析/过期工作项、候选帧及完整帧回调。
- `acquisition` / `ssf_mems_acquisition_init(data)`：独立采集模块的线程、等待队列、调速统计和连接状态，在 IIO 注册前初始化、注册成功后启动。

`ssf_mems_protocol_init()` 先设置手册默认值（从站地址 1、9600、无校验），再调用私有的 `ssf_mems_protocol_parse_properties()` 解析从站地址、`current-speed` 和 `sange-cbm,parity`。属性缺失或读取失败时，逐项记录 info 日志并保留该项默认值，继续解析其他属性；不受支持的 `current-speed` 同样回退到 9600，从站地址/校验位非法仍报错。`current-speed` 同时决定初次匹配速率和匹配后的目标速率；主机控制器拒绝非默认启动速率时也回退到 9600。调用 init 前必须设置有效的 `data->serdev`，不需要打开串口。

serdev 打开后，`ssf_mems_protocol_configure_serial()` 统一配置主机波特率、校验位和关闭流控，记录控制器实际速率；`core.c` 只调用接口，不直接管理串口参数。probe 自身不发起 Modbus 请求；IIO 注册后启动采集线程，等待 1 秒后异步匹配/修改波特率并轮询特征。不写入 40103；需要修改波特率时由协议层执行保存/重启。

core 的 `write_wakeup` 回调转发到 `serdev_device_write_wakeup()`，让同步
`serdev_device_write()` 在控制器只能部分写入时可以被唤醒并继续发送。

`protocol.parity` 在初始化时设为无校验，启动属性解析时按 `none/odd/even` 更新，主机 UART 配置时读取并转换为 Linux 的 `serdev_parity`；请求层读取它，按每字节 10/11 位计算发送超时。目前没有运行时读取、扫描或修改传感器校验位的专用接口，启动配置必须与传感器已生效的参数一致。

`ssf_mems_protocol_set_baudrate()` 在旧速率下依次写 40102 和 40110=1，每次均要求正确的 0x06 回显。40110 对应帧内地址 0x006D，触发保存 40101～40105 并重启。收到保存应答后持总线锁休眠 `SSF_MEMS_SENSOR_REBOOT_DELAY_MS`（`protocol.h`，默认 1000 ms），期间其他主动请求不能发送；随后清理旧接收数据，切换主机速率并读取 40102 验证。成功才返回 0，采集模块另读取完整特征确认可采集。

重启验证最多读取 `SSF_MEMS_BAUDRATE_VERIFY_ATTEMPTS`（默认 8）次，仅在
`-ETIMEDOUT` 时重试。重试等待至少 `SSF_MEMS_BAUDRATE_VERIFY_RETRY_MS`
（默认 100 ms），请求层还会执行已有的超时隔离，因此 `echo` 可能等待数秒。
重试只读取 40102，不再次写 40102/40110，也不重新保存 Flash。读到正确配置
才成功；异常应答、配置值不匹配、信号中断和卸载立即结束。一旦超过尝试次数
仍返回超时，不能把设置主机 UART 当成传感器配置成功。

保存回显丢失/损坏时返回错误，不将超时当成功，不在函数内自动重发 Flash 保存；仍留出重启静默期。保存已确认但新速率验证失败时，也不盲目恢复旧速率，因为设备可能已持久保存并重启。重启或保存尝试使旧特征缓存失效。默认等待是保守起点，需按实机最长启动时间调整，不是手册保证的启动时长。

锁都封装在所属模块的状态内。初始化只用于尚未投入使用的状态，不能直接对运行中的状态重复初始化。接收清理负责停止工作项并释放 FIFO/候选帧，请求清理负责唤醒等待者。卸载时先关闭请求模块，以中断采集线程的在途请求，再停止线程，注销 IIO，最后释放接收状态。传感器业务状态和纯帧编解码没有额外动态资源需要释放。

`protocol.mode` 区分普通通信、原始启动、原始收流和恢复未确认。
普通请求在非普通模式返回 `-EAGAIN`，不会发送数据；恢复确认使用
`ssf_mems_modbus_read_reg_recovery_locked()`，由协议层持有总线锁，仅发送读取。
它也允许卸载期间读取确认，但不解除 `shutting_down`，普通调用仍被拒绝。
`protocol.baudrate` 保留普通配置速率，原始模式临时切速只改变 `host_baudrate`。

## 接口迁移

业务接口已从 `ssf_mems_modbus_*` 改为 `ssf_mems_protocol_*`，声明统一在 `protocol.h`：

- `ssf_mems_protocol_decode_features()`
- `ssf_mems_protocol_read_features()`
- `ssf_mems_protocol_get_features()`
- `ssf_mems_protocol_write_work_parameters()`
- `ssf_mems_protocol_get_baudrate()`
- `ssf_mems_protocol_set_baudrate()`
- `ssf_mems_protocol_invalidate_features()`：断线、切换或读失败导致缓存过期时使快照失效，下一次完整成功读取恢复有效。

通用 `ssf_mems_modbus_read()`、`ssf_mems_modbus_write_reg()` 和 `ssf_mems_modbus_write_regs()` 仍在请求模块。新增 `ssf_mems_modbus_write_block()` 保留块表的功能码、方向、响应格式和固定范围校验，供业务层执行块命令。请求认领接口现在接收 `data, buf, len`，不再依赖接收模块的 `frame_slot`。`ssf_mems_modbus_plan_request()` 也归请求模块，不再属于帧编解码模块。

波特率读取先以当前 serdev 速率读 40102；成功应答所在的速率才是实际通信速率，不能把尚未保存的 40102 暂存值当成已生效速率。只有请求超时（即没有可匹配的正确应答帧）才启动枚举扫描；每个不同实际速率只发送一次读请求，避免 `DEFAULT` 和显式 `9600` 重复。切换前清理旧速率留下的 FIFO/候选帧；成功时保留匹配速率，全部超时或扫描中发生其他错误时恢复入口速率。通用 Modbus 请求、读特征、写工作参数和串口参数操作共用 `bus_lock`；多步操作在整个流程内持锁。发送超时根据当前波特率、校验位和帧长计算，不再固定为 100 ms。

## 不再读取某个特征

从 `ssf_reg_table` 删除对应寄存器的整个初始化项即可，不需要修改业务代码，也不要重编号剩余寄存器的 `display_reg` 或 `protocol_addr`。

例如删除 40002 后，`ssf_mems_protocol_read_features()` 自动发送两次读取：40001（1 个寄存器）和 40003～40029（27 个寄存器）。不用修改块表中的起点和 `reg_count = 29`，这里仍表示原始地址范围，而非剩余表项数量。响应根据实际请求的起始地址映射，后续字段不会前移；删除项对应的缓存字段每轮成功读取后为零。

连续的保留地址会合并读取；表项顺序不影响读取顺序。全部特征项删除时不发送读取请求，缓存更新为全零。分段读取任何一步失败时，不覆盖上次成功的缓存。

通用连续读写不会跳过调用者指定范围内的缺失地址：缺失返回 `-ENOENT`，权限不足返回 `-EACCES`，均不发送请求。固定十参数写入仍要求块内所有寄存器存在且可写，不能通过删表项改变这个固定命令。

## 验证与待处理事项

测试期间，`ssf_mems_protocol_store_features()` 每次成功替换完整缓存后调用
`ssf_mems_protocol_log_features()`，用 `pr_info` 打印 X/Y/Z 的加速度 RMS、峰值、
峰峰值、高频加速度 RMS（g），普通及低频速度 RMS（mm/s），以及声音特征（dB）。
单位直接来自 `sensor_data.h` 的寄存器格式，使用整数商和余数输出两位小数，
不进行内核浮点运算。它们是最新一批统计特征，不是原始瞬时加速度。
每轮成功读取都会打印，包括重复值；读取失败或仅查询缓存时不会打印。
开发板上可用 `dmesg -w | grep 'ssf_mems:'` 观察。
结束测试后仅注释 `store_features()` 中的 `ssf_mems_protocol_log_features(features);`
这一行，即可停用日志并保留函数及声明，供后续测试再次调用。

运行 `python3 tests/protocol/run_tests.py` 可检查删表、分段读取、字段映射、组帧和回调分发。测试分别编译/链接各生产模块，单独编译公共头文件，并检查模块的符号依赖；模拟串口不能替代实际硬件验证。

未认领帧直接丢弃，原有未定义处理入口及编译报错提醒已经移除。私有原始数据格式尚未实现，通用读取会明确返回 `-EOPNOTSUPP`。
