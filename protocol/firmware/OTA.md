# 传感器串口 OTA

本接口仅在已确认协议的 XYZS 型号启用；XYZ V2.4 不暴露 OTA 属性，直接调用也返回 `-EOPNOTSUPP`。

驱动支持把应用程序 `.bin` 经现有 serdev/RS485 连接发送给温振声传感器。
本文件只说明驱动接口、镜像要求和必要的串口包格式。CAN 升级格式不适用于此接口。

## 镜像和接线要求

- 使用**匹配 SSF-MEMS-XYZS 硬件、按 `0x08020000` 链接**的应用 bin，
  从文件第 0 字节开始就是应用向量表。应用启动代码也须将中断向量表指向应用区。
  不是 ELF、HEX、Bootloader bin，也不是包含 Bootloader 的全 Flash 镜像。
- 驱动检查文件不超过 262144 字节、初始栈指针位于支持的内存范围且 8 字节对齐，
  并要求 Thumb 复位入口位于本镜像应用区。
  尾块由驱动填充 `0xff`，用户无需手动补齐。
- bin 不带机型/签名元数据，以上检查不能证明机型匹配，也不能证明设备已安装
  正确 Bootloader；需要固件提供方确认。必须保持稳定供电直至升级和重启完成。
- **RS485 总线上只能接这一个目标传感器。**升级不能依赖普通 Modbus 的单播隔离，
  其他同类设备必须从总线断开。

当前没有已确认适用于这个传感器的升级镜像，仓库中的 bin 属于其他传感器。
不要把它作为本设备的升级候选，也不据此修改参考工程的链接配置。
下面文件名和进度仅为接口示例，需取得匹配此硬件和 Bootloader 的镜像后才能实际升级。
离线回归全部使用合成镜像和故障输入，不读取仓库 bin。

## 在开发板上使用

需要内核 `CONFIG_FW_LOADER`（项目 Kconfig 已选择）；目标板 5.10 配置已有支持。
以下命令以 root 执行，`iio:deviceX` 替换为 `name` 等于 `ssf_mems_xyzs` 的设备。
文件路径是在**开发板**上，不能使用本机路径：

```sh
install -m 0644 /path/to/xyzs_app.bin /lib/firmware/xyzs_app.bin
IIO=/sys/bus/iio/devices/iio:deviceX
cat "$IIO/sensor_online"          # 等待正常上线，值为 1
printf '%s\n' xyzs_app.bin > "$IIO/sensor_firmware_update"
cat "$IIO/sensor_firmware_update_status"
```

文件名只接受字母、数字、点、下划线、连字符，必须以 `.bin` 结尾，最长 127 字节，
不接受目录、开头的点、空格或内嵌 NUL。通过 `request_firmware_direct()` 加载，
文件不存在立即失败，不等待用户态 firmware fallback。加载和镜像校验失败不发送串口帧。

写入是**同步操作**，会等待当前原始采集窗口和在途批次收尾，然后独占采集锁与总线锁。
这可能先等待配置的 60 秒原始窗口加批次收尾时间，再开始传输；不要给写入套短 `timeout`。
另开终端可随时查看 `sensor_firmware_update_status`，它只获取独立短锁：

```text
sending 1024/4096 error=0 version=-1 blocked=0
complete 4096/4096 error=0 version=5101 blocked=0
```

`acknowledged/total` 计入原始文件字节数，不含尾包填充。`version=-1` 表示尚未读到
重启后的版本号；升级到同版本时不要求版本数字变化。阶段依次为 `loading`、
`waiting`、`checking`、`sending`、`rebooting`、`verifying`，最后为 `complete`、
`failed` 或 `uncertain`，未操作时为 `idle`。`error` 为负 errno，`blocked=1`
表示自动串口通信仍被暂停；即使后续另一次文件加载失败，也不会清除这个标志。

传输保持当前双方已匹配的波特率/校验位（通常为工作速率 128000），不为升级写 40102、
40103 或 40110。原始与特征采集都在升级期间暂停。成功后沿用原采集模式与窗口，
按既有连接流程重新验证并恢复采集，沿用驱动本次运行记录的工作速率与采样率目标；
其他未由驱动保存的临时寄存器设置仍由固件决定。
IIO buffer 中已有的旧记录不会清空，应用应结合时间戳区分升级前后的数据。

## 线上协议与重试

| 字段 | 请求 | 应答 |
| --- | --- | --- |
| 地址 | 1 字节；升级须使用单设备总线 | 回显 1 字节 |
| 功能码 | `0x41` | `0x41` |
| 包号 | 4 字节，大端，从 0 开始 | 4 字节，大端，下一期望包号 |
| 载荷 | 固定 256 字节 | 无 |
| 校验 | 前 262 字节求和取低 8 位 | **无 CRC，也无校验和** |
| 总长度 | **263 字节** | **6 字节** |

普通包序号依次为 `0, 1, ...`；最后一个有数据的包将序号替换为 `0xffffffff`，
不是先发完所有数据再附加空结束包。末包提交后等待计数应答和设备重新上线。
满 256 KiB 镜像恰好 1024 包，不再额外发送结束数据块。

驱动首先发送包号 `0xfffffffe` 的只读查询包，取得当前下一期望包号。
必须返回 0 才开始新镜像，
防止上次中断留下的首包被当作同序号重复包，混合两份 bin。普通 Modbus 版本读取
在查询前执行，也沿用请求层的空闲和超时隔离。整个过程无需“进入 OTA”寄存器。

每次发送前保留 20 ms 间隔、清理残留应答。应答等待预算为 5 秒；串口写入
超时另外按包长、实际速率和校验位计算。查询和普通包最多尝试 3 次，普通重复包要求返回对应计数确认。短写/串口错误立即停止，不能补发尾部或假定固件忽略了短包。
未知包计数停止升级，绝不跳包。

**末包只发送一次。**即使应答丢失、发送返回错误、用户信号打断或卸载，驱动仍保持
总线静默至少 15 秒，等待设备重新上线；之后最多进行 15 次原通信参数下的版本读取。
普通包中断后也预留 5 秒再恢复普通通信。这些保守等待预算仍需实机测量确认，
不是设备完成时间的保证。
信号中断转换为 `EINTR`，避免 `SA_RESTART` 自动重做整个 sysfs 刷写操作。

## 失败后的处理与能力边界

- `failed`：未尝试提交末包。缺失文件、错误镜像、设备未上线、上次包计数非零等
  都会失败。若已传过普通包，按设备维护流程重启并确认包计数归零，再显式重新升级。
  不支持断点续传，也不自动保存/重启来清计数。
- `uncertain`：末包可能生效，不能当作升级失败而立即再次发送末包。驱动停止自动
  采集、波特率扫描和配置通信，相关配置 IIO 操作返回 `EBUSY`。先检查供电、启动
  和通信状态；确认后可以重新绑定驱动恢复正常通信，或使用正确镜像显式发起新升级。
  新升级仍须通过“包计数为 0”的预检。重新绑定会按现有策略匹配工作波特率。
- `complete`：全部包计数应答和重启后的版本寄存器读取成功。**不是整镜像哈希、
  签名或 Flash 读回校验成功**。该接口只有包计数应答和重启后通信确认，
  驱动不能据此证明整镜像完整性或提供可靠回滚。
