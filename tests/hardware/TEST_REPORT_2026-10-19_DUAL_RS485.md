# 双 RS485 温振声传感器实机测试

日期：2026-10-19，开发板 `192.168.31.165`，Linux 5.10.160 / ARM64。
两个接口各接一只温振声传感器（XYZS），从站地址均为 1，固件版本均读回 5100。

双实例创建、同时采集、模式隔离、扫描布局和卸载重载验证通过。
**本次不是全部通过：RS485-2 的配置 API 测试出现一次 ETIMEDOUT，另有 RS485-1 的 6 条 CRC/长度日志未定位。**
后续读取成功不抵消原始失败，也没有修改驱动超时、增加重试或调整判定阈值来掩盖问题。

## 设备树修改与部署

修改的内核源码为：
`/home/u-yoimiya/rk3588/kernel/arch/arm64/boot/dts/rockchip/overlay/rk3588-lubancat-5io-rs485-2-overlay.dts`。
在 UART7 的 overlay 下增加传感器子节点，保留现有引脚与 RS485 方向控制配置：

```dts
ssf-mems {
    compatible = "sange-cbm,ssf-mems-xyzs";
    sange-cbm,slave-id = <1>;
    current-speed = <9600>;
    sange-cbm,parity = "none";
};
```

编译命令执行成功；使用板端实际的基础 DTB 和两个 overlay 合并检查，两个传感器节点均存在。
基础设备树合并产生的 dtc 告警另存于证据包，不将合并检查描述为无告警构建。

```sh

  rockchip/overlay/rk3588-lubancat-5io-rs485-2-overlay.dtbo
```

## 自动连接与双路同时采集

RS485-1 已在 128000；RS485-2 从 9600 自动匹配并切换到 128000，日志记录一次
40102=8、一次 40110=1 保存/重启，并在新速率下读回确认。两路采样索引最终均为 6（5333.4 Hz）。
后续卸载重载没有再次保存/重启传感器。

两路同时记录原始与特征 IIO，计划每路 300 秒，按完整 1024 点批次结束。
本次是交替窗口中的间歇定长采集，不是连续 300 秒、5333.4 Hz 无间断输出。

| 接口 | 实际记录时间 | 原始记录 / 完整批次 | 特征记录 | 摘要与二进制检查 |
| --- | --- | --- | --- | --- |
| RS485-1 | 300.098 s | 38912 / 38 | 119 | 通过 |
| RS485-2 | 300.085 s | 37888 / 37 | 119 | 通过 |

原始扫描 24 字节，特征扫描 72 字节。逐条检查包号、包内点号、时间戳和填充，
两路错误均为 0，文件均从 0/0 开始、在 15/63 结束，无尾部残批。
原始有效段及排空段 CRC/序号、IIO 丢样、忽略字节的监测值均为 0。
最大原始/特征空档分别为 RS485-1 的 9.421/11.130 秒、RS485-2 的 11.146/11.140 秒；
时间戳覆盖分别为 288.908 和 289.362 秒，记录开始包含自动连接等待。

内核日志中 RS485-1 出现 6 条 `invalid frame CRC/length: -74`，集中在启动后约 185.9～190.0 秒；
RS485-2 对应时段没有这类日志。它们未伴随本轮后台请求失败、离线或已交付数据序列错误，
但没有线级抓包来确定原因，不能据此断言它们无害，也不能称整个通信过程“零 CRC 异常”。
IIO 文件不保留 Modbus 帧 CRC；二进制检查验证的是交付数据布局和序列。

## 双实例隔离与 IIO 边界

将两路主机轮询周期分别设为 700/1300 ms，各执行约 20 秒的相反模式组合，再交换。

| 阶段 | RS485-1 | RS485-2 |
| --- | --- | --- |
| 第一阶段 | feature：特征 27 条，原始 0 条 | raw：原始 4096 条，特征 0 条 |
| 交换后 | raw：原始 4096 条，特征 0 条 | feature：特征 15 条，原始 0 条 |

两路仅输出各自所选数据流；原始模式读取旧特征缓存返回 ENODATA；包序列、填充及时间戳检查通过。
结束后恢复两路原有 alternating / fixed / 1000 ms 配置。

两路的 `invalid-buffer` 与 `layouts` 用例分别通过：空扫描掩码、仅时间戳掩码返回 EINVAL；
运行中修改掩码返回 EBUSY；单轴、混合宽度、无时间戳、特征子集、全部特征无时间戳及
8 位标志加时间戳六种布局的扫描长度和填充均符合实际 ABI。

## 配置 API 的失败与复核

RS485-1 完整 API 用例通过：13 项非法输入被拒绝，采样率/特征开关同值写读回一致，
四线程共 12 次配置快照一致，比例属性正确；128000 同值写耗时 0.184 秒，未触发改速或保存/重启。

**RS485-2 完整 API 用例失败**：非法输入检查后的第二次配置快照读取
`sensor_sampling_rate_index`，253.648 ms 后返回 errno 110（ETIMEDOUT）。
失败发生在波特率同值写和四线程读取之前，因此这些后续项目不能算作 RS485-2 已通过。
原始退出码、回溯及当时内核/UART 日志均保留，未用复跑覆盖。

随后进行独立只读复核，每路在 alternating、feature 模式各读取 70 次配置，共 280 次，
均未出错，最大单次耗时 26.303 ms。复核结束两路仍在线并恢复原模式。
这些快速读取不保证覆盖所有原始/特征窗口切换边界；结果仅表明未复现，**超时根因仍未定位或修复**。
当前证据不足以区分传感器响应、串口接收与驱动时序原因，也不足以认定是双实例串扰。

## 卸载、重载与结束状态

关闭测试 buffer 后正常卸载模块，四个传感器 IIO 设备均消失，仅剩板载 ADC 和 IIO trigger 项。
卸载日志中的 status -19 对应主动退出。重新加载同一模块后，两路自动上线，
再次同时采集 60 秒，每路均收到 6144 条原始数据（6 个完整批次）和 23 条特征，
两路摘要与严格整批检查均通过。这不是持有活跃用户句柄时强制卸载测试。

最终逐实例读回：在线 1、128000、采样索引 6 / 5333.4 Hz、固件 5100、
alternating / fixed / 1000 ms，四个 buffer 均关闭，原始 CRC/序号/丢样/排空错误和忽略字节均为 0。
无残留采集测试进程。驱动保持手动加载状态，未新增开机自动加载配置；设备树修改已安装到启动分区。

测试工具的 21 个离线单元测试及 `git diff --check` 通过。
本次未做 XYZ 型号实机测试、OTA 升级、计量标定、断电持久性或长期可靠性测试。
此前被开发板重启中断的单接口记录不计入上述双路通过时长。
