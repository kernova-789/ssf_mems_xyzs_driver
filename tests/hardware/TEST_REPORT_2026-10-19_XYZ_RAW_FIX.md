# XYZ V2.4 定长采集修复与结构审查

## 结论及边界

两只 SSF-MEMS-XYZ V2.4 的定长采集在 128000 波特率、采样率索引 0..3
（533.34、888.9、1066.68、1333.35 Hz）下已取得完整批次。
驱动默认工作采样率调整为索引 3，并在触发前拒绝超过线速预算的原始采集组合。
这次修复不意味着 128000/5333.4 Hz 已可使用；此组合在线上已经产生损坏数据，
驱动不能恢复未发送或被覆盖的样本，也没有放宽 CRC 或序号校验。

所有正式驱动测试通过 IIO 进行。脚本只设置参数、读取和校验结果，
不代替驱动组帧、接收、恢复总线或实现两路隔离。OTA 未实现或改动。

## 现场及抓包

- 开发板：192.168.31.165，Linux 5.10.160，RS485-1 为 UART4/serial0-0，
  RS485-2 为 UART7/serial1-0。两路 compatible 均为 `sange-cbm,ssf-mems-xyz`。
- 独立抓包模块：`recovery_lab/mems_xyz_wire.c`。抓取接收回调看到的字节，
  未经过正式驱动的 FIFO、原始解析器或 IIO；实验结束后已卸载。
- 128000/5333.4 Hz：两路都收到六个 392 字节包，包号 0、3、6、9、12、15，
  前五包 CRC 错误，仅末包正确。显式写入并读回 U32 长度 1024 后仍复现。
- 仅把采样率改为 533.34 或 1333.35 Hz，两路都收到 6272 字节，
  即 16 包、包号 0..15、CRC 全部正确。

包格式与现有解析器一致。5333.4 Hz 的 392 字节/64 组、8N1 传输至少需要
约 326671 bit/s，超过 128000。两只样机表现与实时发送吞吐不足、发送缓冲覆盖
或丢包相符；未取得 XYZ 的固件源码，不声称已定位其内部具体实现。

## 代码设计

1. `sensor/xyz.c` 保存型号特有的最低线速表。值由包长度、每包样本数、
   采样率和 20% 余量在编译期计算，不保留难以追溯的数字列表。
2. `sensor/sensor.h` 描述可选线速约束及普通采样长度编码数量，
   `sensor/sensor.c` 检查表长度和合法性。XYZS 不设置线速表，原有行为保持不变。
3. `protocol/raw/raw_capture.c` 在总线锁内读取实际采样率，再检查型号约束。
   不支持时不写长度、不触发、不使特征缓存失效；返回 `-EOPNOTSUPP`。
   长度配置、1024 组批次接收、CRC/序号校验、总线恢复继续使用共用实现。
4. `acquisition/ssf_mems_acquisition.c` 区分参数不支持与通信失败。
   交替模式继续特征窗口；纯原始模式保持用户选择、至少间隔 1 秒重试，
   避免离线重连和忙轮询。没有新增 XYZ 型号分支或自动降采样逻辑。
5. 普通采样长度通过已有配置接口开放写入，范围由型号提供；
   写后读回、同值不重复写。40053 与定长采集的 40061/40062 分开，
   恢复普通长度 4096 不改变驱动每批 1024 组的设计。
6. 实机内核 IIO 合并属性时不执行原属性组的 `is_visible`。
   现在注册前按能力生成实例自己的属性列表，列表和 `iio_info` 与 IIO 私有区
   同时分配、同时释放。XYZ 不支持的开关、版本及升级节点不再出现。
   没有内核版本判断，未修改内核，也没有实现 OTA。

结构审查结果：型号、寄存器和约束在 `sensor`；协议层执行共用事务和校验；
采集层调度；IIO 呈现通道与配置。没有根据型号名称、指针或设备编号打分支，
没有错误后换解析格式、忽略 CRC、自动改用户采样率或借助外部脚本维持采集。
临时诊断模块仅在 `tests/hardware/recovery_lab`，不参与正式模块链接。
日志中的历史 driver 名称 `ssf_mems_xyzs_driver` 保留兼容用途；实际绑定型号
由 OF 匹配数据决定，IIO 名称为 `ssf_mems_xyz`。

## 实机回归

下列记录均逐条检查 24 字节原始 IIO 扫描中的包号、包内序号、时间戳和填充。
特征全通道记录按 ARM64 对齐为 48 字节。采集均收至完整批次边界。

| 阶段 | RS485-1 完整批次 | RS485-2 完整批次 | 原始记录错误 |
| --- | ---: | ---: | ---: |
| 吞吐约束修复后，双路索引 3，180 秒 | 49 | 51 | 0 |
| 索引 0 / 索引 3，30 秒 | 2 | 9 | 0 |
| 索引 1 / 索引 2，40 秒 | 7 | 11 | 0 |
| 配置接口整理后，双路索引 3，60 秒 | 16 | 16 | 0 |
| 属性注册审查后的最终模块，双路索引 3，40 秒 | 11 | 11 | 0 |

上述二进制共 183 个批次、187392 组 XYZ，独立离线复核均无残缺批次、
序号错误、时间戳倒退或填充错误。原始接收统计为零 CRC 错误、
零序号跳变、零 IIO 丢样；完整二进制和摘要保留于证据包。
180 秒阶段属于较早的吞吐修复版；最终属性注册代码另做了最后一行的实机复核。

另做单路不支持组合的隔离验证：RS485-1 选择 128000/5333.4 Hz，
RS485-2 保持 128000/1333.35 Hz。25 秒内前者原始记录 0、特征记录 25；
后者原始记录 6144、特征记录 15，原始包序号无错误。
回归中发现的参数不支持导致重连问题已修复，最终不支持组合不使设备离线。

普通采样长度两路均测试 5→2、同值 2、非法 6；非法值返回 EINVAL，
读回仍为 2。完成定长原始采集后，普通长度仍为 4096，证明两个长度独立。
最终两路均确认不存在 XYZ 不支持的五个开关/版本/升级属性。

限制：较早长测记录过一次特征请求超时；低档测试中有普通帧候选 CRC 日志。
这些没有造成原始批次损坏，本报告不宣称所有通信全程零错误。
高波特率表项仅为吞吐预算，没有据此声称高档位已通过实机可靠性验证。
主机批次完整性也不能独立证明传感器内部的采样时钟或测量精度。
