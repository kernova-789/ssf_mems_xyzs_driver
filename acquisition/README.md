# 自动采集模块

`ssf_mems_acquisition.c/.h` 管理每个传感器实例的采集线程、等待队列、连接状态、
波特率目标、IIO 数据发布及退出。`acquisition_routes.c/.h` 集中保存路线、模式名称、
型号能力、时长字段、Buffer 条件和单次采集方法。`acquisition_policy.c/.h` 负责完整快照比较、
轮询周期调整和通信失败判定，不执行串口操作。

`ssf_mems_firmware.c` 提供同步固件升级入口：先加载和校验 bin，再获取采集锁等待
当前批次收尾，交给 `protocol/firmware/ota.c` 独占总线传输。锁顺序是 OTA `update_lock` →
采集 `lock` → 协议 `bus_lock`；进度和应答使用独立的 OTA 短锁。
成功后沿用原模式/窗口请求重新连接；末包结果不确定时设置 `firmware_blocked`，
后台停止串口操作，IIO 波特率/传感器配置接口返回 EBUSY。再次成功升级或重新绑定
才解除该暂停，普通调度模式修改不解除。参见 [OTA 使用说明](../protocol/firmware/OTA.md)。

## 启动与连接

core 在 IIO 注册前初始化采集状态，注册成功后启动 kthread。线程先等待 1000 ms，
再调用现有波特率查询/扫描接口匹配传感器。启动时先使用设备树 `current-speed`，
该值仅为初次匹配提示；缺失、读取失败、不受支持或被控制器拒绝时以 9600 开始。
正式通信目标取自型号表的 `default_work_baudrate`，当前为 128000，
原始定长上传和特征请求共用该速率。
初次请求无响应时，扫描传感器实际速率，再将双方设置为目标值；所有速率都无响应
则退避重试，不盲目写入配置。
匹配速率已经是目标时不重复写 40102。修改由协议层完成保存/重启等待和新速率
验证，再额外等待 20 ms，调用协议层将采样率设为本次运行的目标索引。
首次绑定采用型号表默认值，当前为索引 6（5333.4 Hz）。
采样配置写入并读回确认后，选择了特征路线时完整读取特征寄存器确认可采集，
这一轮也发布到缓存和已启用的 IIO buffer；未选择特征路线的模式只验证配置，不读取特征。

采样率配置使用 0x06，读到已为目标值时跳过写入；配置失败时不进入在线轮询，
按连接失败流程退避并重新匹配。此步骤在每次连接/重连时执行，普通轮询不写配置。
驱动读回确认采样率，不额外发送 40110 或重启；实际生效和掉电保留行为需按目标设备确认。
在线日志中的采样率代表已确认的配置寄存器值，不代表已产生新测量。
通过 IIO 修改采样率并确认成功后，驱动将其记为本次运行的重连目标。
写入失败或参数非法时不改变目标；若写入已生效但确认丢失，后续重连仍恢复原目标。
卸载再绑定后重新采用型号表默认值。

当前默认索引 6 对应 5333.4 Hz，定长原始批次为 1024 组 XYZ。
传感器采样率与特征刷新频率独立，修改采样率不保证按比例缩短特征刷新时间。
需要其他频率时，应设置后验证实际输出，参见 tools/README.md 的排查说明。

生效流程：传感器以旧波特率回复 40102 写入，此时只修改暂存寄存器。主机继续
用旧速率写 40110=1，确认保存应答并等待重启（保守静默 8000 ms）后才修改 UART，
读取 40102 验证。重启后的读取超时允许最多 8 次只读验证，保留超时隔离，
不重复发送保存/重启命令，以容纳固件启动较慢的情况。不修改传感器校验位，
不扫描校验位；主机继续使用初始化时的配置，默认无校验。

普通扫描/写入请求的响应超时为 200 ms。特征读取额外预留最长普通寄存器响应
的传输时间，以支持手动选择较低速率。波特率仍由协议模块管理，采集模块不直接
调用 serdev 配置接口。

请求层会在每次发送前检查接收空闲并清理残留帧；通信失败后另有至少 1000 ms
的迟到应答隔离窗口。因此异常时的重试、完整波特率扫描和进入重连的耗时会增加，
上述 200 ms 仅指单次请求的响应等待，不代表整个扫描的最长耗时。

## 轮询和数据有效性

以下轮询规则适用于特征模式以及交替模式的特征窗口。

每轮调用 probe 绑定的 `data->sensor_ops->read_features()`，只采集当前型号表中的特征；XYZS 为 40001～40029，XYZ 为 40001～40019。
这些是特征寄存器，不轮询配置寄存器或触发原始数据传输。分段读取必须全部成功才更新
缓存。成功后取出完整快照，并调用 `ssf_mems_iio_publish_features()`，即使结果
重复也发布：重复值本身不能证明没有产生新样本。buffer 发布错误不触发串口恢复。

默认使用固定周期 1000 ms，可通过 IIO 切换为 `adaptive` 或修改固定周期。
固定周期、自适应周期下限/上限分别保存，互不覆盖；自适应默认范围为 500～5000 ms。
三项周期均允许 100～60000 ms，下限不得超过上限。传感器实测约每 4.4～4.8 秒
更新一批，默认 1 秒轮询通常每批读取 4～5 次。
周期指两轮开始时间的间隔，读取耗时
从等待时间中扣除；如果读取已超时或超过周期，则保留至少 2 ms 的帧间等待。
低速 UART 按实际速率和既有校验配置延长该等待。读取耗时超过配置周期时，实际
采集周期相应变长，不会并行发送请求或补发积压轮次。

固定模式不执行样本比较或自适应统计。自适应模式每 32 次相邻成功快照比较形成
一个窗口。全部字段相同计为一次重复；依据 `sensor_fields.h` 的公共字段清单逐字段比较，
不比较结构体填充字节。重复比例 >50% 时，周期增加约 20%；<10% 且窗口最大
读取耗时不超过当前周期的一半时，周期减少约 5%；其余保持不变。每个窗口只调整
一次。每 30 秒仅在本轮数据发生变化、当前窗口重复率低于 10%、读取耗时允许时
尝试小幅提速；首次读取没有可比较的样本，不触发试探。试探不清空未完成的比较窗口；同一轮
窗口和试探同时到期时优先窗口决策。所有调整都限制在用户设置的范围内。
失败打断比较窗口，重连清空旧统计，但保留用户配置和已学习的周期。
正常定长批次收尾只更新链路健康状态，不清空统计，因此交替模式也可积满比较窗口。
静止和量化同样可能产生重复结果，不能据此确定真实更新率。

切换轮询模式时清空旧比较统计；进入自适应时把当前周期限制到新范围，返回固定
模式时使用保存的固定周期。修改当前模式的参数会唤醒调度，但不重新开始特征窗口。
修改另一个模式的参数只保存供下次切换使用。设置只保存在本次绑定的驱动内存中，
不写传感器、不保存 Flash；卸载后恢复默认值。属性和使用示例见
[IIO 轮询配置](../iio/README.md#特征轮询周期)。

读失败时不发布样本。距离最近完整成功读取达到 3 秒后使缓存失效；进入重连、
主动切换波特率和退出时也立即使缓存失效。内容保留，但 `*_raw` 返回 `-ENODATA`，
直到下一轮完整读取成功。第一次成功采集之前同样没有有效缓存。
缓存过期仍以最近成功读取的时间为准，而非特征值上次变化的时间；重复读取同一批
数据不会误判为掉线。当前是在读取失败后检查 3 秒失效条件，并不独立运行过期定时器；
较长轮询周期下，两次成功读取之间仍保留上次的有效缓存。

## 恢复及控制

超时、发送 I/O 错误和 CRC 错误计入通信失败。累计至少 5 次且距离最近一次
已确认通信至少 3 秒时，暂停轮询并进入重连。完整成功采集和合法 Modbus 异常
应答都会清除通信失败计数；合法异常应答不触发波特率扫描。参数/表项等本地错误
也不触发波特率扫描，错误日志限速输出。

重连优先使用当前/最后匹配速率，失败后复用协议扫描，重新应用目标波特率并验证。
连接失败后的等待依次为 1、2、4、8、16、30 秒，上限为 30 秒。40102 暂存应答
或 40110 保存应答丢失时，不假定整个切换已经成功，下一次恢复重新匹配实际速率。

`sensor_baudrate` 的读写通过采集模块互斥量与整个采集步骤串行化。写入仍为同步
操作；成功后同时更新本实例的恢复目标，后台保留手动指定的波特率。随后由采集线程
验证并恢复轮询。写入失败返回原错误，同时请求重新匹配，恢复目标保持原值。
目标仅在本次绑定期间保留，下次绑定重新采用型号表默认工作目标，当前为 128000。手动波特率重连流程同样
恢复本次运行保留的目标采样率。

新增只读 IIO 属性：

- `sensor_online`：最近验证过的链路是否处于轮询状态（0/1）。短暂失败尚未达到
  重连阈值时仍为 1；合法异常帧证明链路可达，但不代表有新样本。
- `sensor_poll_interval_ms`：当前配置的轮询周期，实际周期可能受读取耗时影响。
- `sensor_sample_age_ms`：距离最近完整成功采集的时间；从未成功时返回 `-ENODATA`。

启动、请求超时、切换等待、退避和轮询休眠都可以被停止流程唤醒。core 卸载时先
关闭请求模块，拒绝新请求并唤醒在途请求，再停止/等待采集线程，最后注销 IIO、
释放接收状态。锁顺序为采集互斥量 → 协议总线锁 → 请求锁；接收回调不获取采集锁。
IIO 发布另持 `indio_dev->mlock` 同步 buffer 开关；buffer 回调不能反向获取采集锁。
常规轮询、启动和退避休眠不持锁；20 ms 切换稳定等待期间保留采集锁，防止手动
波特率操作打断切换验证，但不持协议总线锁。

## 调整与验证

排查未切换到目标配置时，先确认开发板实际卸载旧模块并加载新的 `.ko`。
复制模块文件不改变已经加载的驱动。初始化日志 `acquisition configuration`
显示型号表中的初始工作目标和采样率（当前为 128000、索引 6）；设备树仅提供匹配提示。
`sensor matched` 显示匹配到的实际
通信速率。协议日志分别标记 40102 暂存、40110 保存/重启、UART 切换和重启后
验证，采样率读回成功才打印 `sampling configuration verified`。
只有最后的 `sensor online` 表示连接配置成功；选择了特征路线时还完成完整特征读取，
其余模式在配置验证后进入批次调度，不读取特征。
波特率切换失败时不会继续设置采样率，不能把目标配置日志当成生效证明。

开发板可用 `dmesg -w | grep -E 'acquisition configuration|sensor matched|baud change|40110|sampling|sensor online|sensor connection failed'`
保留各阶段的结果。源代码检查和模拟测试无法证明板上的配置已生效。

默认工作波特率和默认采样率在 `sensor/xyz.c` / `sensor/xyzs.c` 的型号描述中；
启动/切换等待、请求超时和退避初值在 `ssf_mems_acquisition.c` 中；
调速窗口、阈值周期及失败条件在 `acquisition_policy.h` 和对应 `.c` 中。

运行 `python3 tests/acquisition/run_tests.py` 检查调速边界、读取耗时、结构体填充、
计时回绕、启动/验证、掉线重连、合法异常帧、退避上限、手动改速率、丢应答和退出。
测试使用可控时钟和串口替身，不验证真实 UART 时序或内核线程调度。
## 三路线调度与批次边界

`feature`、`raw`、`sound` 分别选择单一路线；`sound` 仅在型号提供声音能力时可用。
默认 `alternating` 按 FEATURE → RAW → SOUND → FEATURE 环形轮转；
XYZ 默认使能特征、振动，XYZS 默认使能三项。`sensor_alternating_*_en` 可剪裁组合，
至少保留一项。三种窗口默认各 5000 ms，范围 100..60000 ms。
旧设备树 `raw-duration-ms=0` 仍选择 feature；有校验时默认 feature。

采集层持有统一 `phase_until`，每次只调用一次 `read_features()`、`collect_raw()` 或
`collect_sound()`；后两者的职责都是一个完整批事务。协议层负责触发、接收校验和
只读恢复，不再维护振动时间窗口。每批结束释放采集锁；窗口到期收完在途批次，
下一轮选择下一可运行路线，不补发积压批次。纯 raw/sound 重复有限批次，并非连续波形。

自动振动/声音路线需要对应 IIO `buffer/enable=1` 并选择实际数据通道；
未启用的路线立即跳过，无可运行路线时每 1000 ms 复查并休眠。
开启字符设备不等于开启 buffer，也不能证明存在持续消费者。
特征路线仍维护 sysfs 缓存，不以特征 buffer 是否开启作为轮询条件。
采集模式不会自动配置、开启或消费 buffer。

振动 `raw_*` 观测统计仍按 raw 窗口累计：第一批重置，后续批只比较本批新增错误，
保持训练工具对 `raw_packets` / `raw_batches` 的原有口径。采样长度变化在下一批使用，
不重启窗口。同步 `raw + manual` 的显式窗口仍使用调用开始时的配置快照，
由同一工作线程重复批事务，返回前确认整个窗口收尾；批次之间可插入声音。

手动 `sensor_sound_capture=1` 与自动调度共用批事务和错误恢复门禁：
排队后由同一工作线程在完整批次边界插入一个声音批次，不要求 POLL，不改原模式、路线开关、
窗口截止时间、振动长度或采样率。恢复未确认则离线退避；IIO 丢样不会触发波特率扫描。
正在自动采声音时手动触发会额外产生一批，用户态应持续消费并区分批次。

## 配置与事务的锁边界

`config` 是 `status_lock` 保护的用户配置；`active_config` 是持有 `acquisition.lock`
的采集线程在批次边界复制的快照。配置复制和 `config_changed` 清零在同一个短临界区内，
避免吞掉并发配置写入。模式、时长、交替开关实际变化后，从第一个可运行路线开启新窗口；
同值写不重置。轮询周期、批次长度修改只唤醒等待，不重启路线窗口。
多属性写入分别生效，不是一次原子事务。

模式、窗口、交替开关、手动标志、长度及轮询配置的 sysfs 写入只持短状态锁，
不等待采集、串口或 OTA。手动调用只提交请求并等待完成，不在 sysfs 线程执行串口采集。
串口配置和升级仍由采集锁串行化；有同步采集请求时，改速率、传感器参数写入及升级返回 EBUSY。
轮询策略统计也在短状态锁内更新；串口等待、IIO 操作和缓存失效均不持该锁。
锁顺序为采集锁 → 状态锁，状态锁不反向请求采集锁；IIO `mlock` 仅短持，
不跨越批次等待。所有实例独立持有配置与调度状态。

完整 ABI 和使用方法见 [IIO 控制](../iio/ATTRIBUTES.md)、[声音采集](../iio/SOUND_CAPTURE.md)。
回归范围及本次验证边界见 [重构验证记录](../tests/acquisition/TDM_REFACTOR_2026-11-06.md)。

## 同步请求与生效状态

每条路线至多保存一个同步请求（包含在途请求），重复提交返回 EBUSY。
手动振动窗口和声音单批由同一工作线程逐批公平仲裁，调用者以 completion 同步等待结果。
显式振动窗口保留提交时的长度/时长快照及累计统计；声音插入消耗同一墙钟窗口，
不会延长该窗口，窗口到期后不再开始新振动批次。
该窗口期间新主机配置继续保存，窗口完成后统一应用，避免混用采样长度和统计口径。

信号取消排队请求时不发送触发命令；取消在途请求时先完成本批安全收尾再返回 EINTR。
不会把仍由工作线程引用的请求留在已返回的调用栈上。卸载、恢复失败或升级暂停会完成等待者。
IIO 注册在先、工作线程随后启动；未在线或没有工作线程时不接受同步采集。

连接阶段 `phase` 与自动路线 `route` 分开。只读 `sensor_acquisition_status` 用一个短锁快照
输出连接、实际路线、busy、手动请求、空闲原因、请求模式/已应用模式及配置版本。
`config_version` 在实际配置修改时递增；`applied_config_version` 在工作线程接纳配置时更新。
两者不等表示配置待应用；相等表示调度已采用该配置，不代表已收到新数据。
模式/时长/开关变化重启路线窗口；长度和轮询配置不重启窗口；相同值不增加版本。

所有原始批次开始前快照 IIO Buffer 代次。批中关闭或重启 Buffer，即使发生在两个发布调用之间，
后续发布也会失败，计入批次交付错误；只选元数据通道也不能作为原始数据就绪。
特征缓存发布保持可选。有限批次的恢复分派由 `protocol/raw/capture_session.c` 负责，
振动与声音实现互不调用，OTA 状态拒绝被按原始流恢复。
