# 自动采集模块

`ssf_mems_acquisition.c/.h` 管理每个传感器实例的采集线程、等待队列、连接状态、
波特率目标、IIO 数据发布及退出。`acquisition_policy.c/.h` 负责完整快照比较、
轮询周期调整和通信失败判定，不执行串口操作。

`ssf_mems_firmware.c` 提供同步固件升级入口：先加载和校验 bin，再获取采集锁等待
当前窗口收尾，交给 `protocol/ota.c` 独占总线传输。锁顺序是 OTA `update_lock` →
采集 `lock` → 协议 `bus_lock`；进度和应答使用独立的 OTA 短锁。
成功后沿用原模式/窗口请求重新连接；末包结果不确定时设置 `firmware_blocked`，
后台停止串口操作，IIO 波特率/传感器配置接口返回 EBUSY。再次成功升级或重新绑定
才解除该暂停，普通调度模式修改不解除。参见 [OTA 使用说明](../protocol/OTA.md)。

## 启动与连接

core 在 IIO 注册前初始化采集状态，注册成功后启动 kthread。线程先等待 1000 ms，
再调用现有波特率查询/扫描接口匹配传感器。启动时先使用设备树 `current-speed`，
该值仅为初次匹配提示；缺失、读取失败、不受支持或被控制器拒绝时以 9600 开始。
正式通信目标固定为 128000，原始定长上传和特征请求共用该速率。
初次请求无响应时，扫描传感器实际速率，再将双方设置为目标值；所有速率都无响应
则退避重试，不盲目写入配置。
匹配速率已经是目标时不重复写 40102。修改由协议层完成保存/重启等待和新速率
验证，再额外等待 20 ms，调用协议层将 40052 设为采样率索引 6（5333.4 Hz）。
采样配置写入并读回确认后，特征/交替模式完整读取特征寄存器确认可采集，
这一轮也发布到缓存和已启用的 IIO buffer；纯原始模式不读取特征，随后开始定长批次。

采样率配置使用 0x06，读到已为 6 时跳过写入；配置失败时不进入在线轮询，
按连接失败流程退避并重新匹配。此步骤在每次连接/重连时执行，普通轮询不写配置。
固件在当前批次处理结束后应用采样率，自动保存至 Flash；启动时读取保存参数，
无需额外发送 40110 或重启。在线日志中的采样率代表已确认的配置寄存器值。
手动修改采样率在当前在线期间有效，下一次重连会再次设为 6。

索引 6 是针对当前敲击和普通振动测试的折中：定长原始批次为 1024 组 XYZ，
硬件低通和配置频段的截止频率约为 2.67 kHz，普通特征仍使用
每轴 1600 点。与索引 9 相比，它保留更长的标称时间窗（约 0.30 s 而非 0.06 s）。
它不覆盖完整的 1～5.3 kHz 高频段；有该频段需求时应选择更高配置并验证滤波设置。
这项选择不保证缩短固件完整批次的更新时间，参见 tools/README.md 的采样流程说明。

生效流程：传感器以旧波特率回复 40102 写入，此时只修改暂存寄存器。主机继续
用旧速率写 40110=1，确认保存应答并等待重启（保守静默 8000 ms）后才修改 UART，
读取 40102 验证。重启后的读取超时允许最多 8 次只读验证，保留超时隔离，
不重复发送保存/重启命令，以容纳固件启动较慢的情况。不修改传感器校验位，
不扫描校验位；主机继续使用初始化时的配置，默认无校验。

普通扫描/写入请求的响应超时为 200 ms。特征读取额外预留最长普通寄存器响应
的传输时间，以支持手动选择较低速率。波特率仍由协议模块管理，采集模块不直接
调用 serdev 配置接口。

请求层会在每次发送前检查接收空闲并清理残留帧；通信失败后另有至少 1000 ms
的迟到应答隔离窗口。因此异常时的重试、完整波特率扫描和进入重连的耗时会增加，
上述 200 ms 仅指单次请求的响应等待，不代表整个扫描的最长耗时。

## 轮询和数据有效性

以下轮询规则适用于特征模式以及交替模式的特征窗口。

每轮调用 `ssf_mems_protocol_read_features()`，只采集表中保留的 40001～40029
特征寄存器，不轮询配置寄存器或触发原始数据传输。分段读取必须全部成功才更新
缓存。成功后取出完整快照，并调用 `ssf_mems_iio_publish_features()`，即使结果
重复也发布：重复值本身不能证明没有产生新样本。buffer 发布错误不触发串口恢复。

默认使用固定周期 1000 ms，可通过 IIO 切换为 `adaptive` 或修改固定周期。
固定周期、自适应周期下限/上限分别保存，互不覆盖；自适应默认范围为 500～5000 ms。
三项周期均允许 100～60000 ms，下限不得超过上限。传感器实测约每 4.4～4.8 秒
更新一批，默认 1 秒轮询通常每批读取 4～5 次。
周期指两轮开始时间的间隔，读取耗时
从等待时间中扣除；如果读取已超时或超过周期，则保留至少 2 ms 的帧间等待。
低速 UART 按实际速率和既有校验配置延长该等待。读取耗时超过配置周期时，实际
采集周期相应变长，不会并行发送请求或补发积压轮次。

固定模式不执行样本比较或自适应统计。自适应模式每 32 次相邻成功快照比较形成
一个窗口。全部字段相同计为一次重复；按字段比较，
不比较结构体填充字节。重复比例 >50% 时，周期增加约 20%；<10% 且窗口最大
读取耗时不超过当前周期的一半时，周期减少约 5%；其余保持不变。每个窗口只调整
一次。每 30 秒在耗时允许时尝试小幅提速，但不清空未完成的比较窗口；同一轮
窗口和试探同时到期时优先窗口决策。所有调整都限制在用户设置的范围内。
失败打断比较窗口，重连清空旧统计，但保留用户配置和已学习的周期。
正常定长批次收尾只更新链路健康状态，不清空统计，因此交替模式也可积满比较窗口。
静止和量化同样可能产生重复结果，不能据此确定真实更新率。

切换轮询模式时清空旧比较统计；进入自适应时把当前周期限制到新范围，返回固定
模式时使用保存的固定周期。修改当前模式的参数会唤醒调度，但不重新开始特征窗口。
修改另一个模式的参数只保存供下次切换使用。设置只保存在本次绑定的驱动内存中，
不写传感器、不保存 Flash；卸载后恢复默认值。属性和使用示例见
[IIO 轮询配置](../iio/README.md#特征轮询周期)。

读失败时不发布样本。距离最近完整成功读取达到 3 秒后使缓存失效；进入重连、
主动切换波特率和退出时也立即使缓存失效。内容保留，但 `*_raw` 返回 `-ENODATA`，
直到下一轮完整读取成功。第一次成功采集之前同样没有有效缓存。
缓存过期仍以最近成功读取的时间为准，而非特征值上次变化的时间；重复读取同一批
数据不会误判为掉线。当前是在读取失败后检查 3 秒失效条件，并不独立运行过期定时器；
较长轮询周期下，两次成功读取之间仍保留上次的有效缓存。

## 恢复及控制

超时、发送 I/O 错误和 CRC 错误计入通信失败。累计至少 5 次且距离最近一次
已确认通信至少 3 秒时，暂停轮询并进入重连。完整成功采集和合法 Modbus 异常
应答都会清除通信失败计数；合法异常应答不触发波特率扫描。参数/表项等本地错误
也不触发波特率扫描，错误日志限速输出。

重连优先使用当前/最后匹配速率，失败后复用协议扫描，重新应用目标波特率并验证。
连接失败后的等待依次为 1、2、4、8、16、30 秒，上限为 30 秒。40102 暂存应答
或 40110 保存应答丢失时，不假定整个切换已经成功，下一次恢复重新匹配实际速率。

`sensor_baudrate` 的读写通过采集模块互斥量与整个采集步骤串行化。写入仍为同步
操作；成功后同时更新本实例的恢复目标，后台保留手动指定的波特率。随后由采集线程
验证并恢复轮询。写入失败返回原错误，同时请求重新匹配，恢复目标保持原值。
目标仅在本次绑定期间保留，下次绑定重新采用正式目标 128000。手动波特率重连流程同样
确认采样率为 6。

新增只读 IIO 属性：

- `sensor_online`：最近验证过的链路是否处于轮询状态（0/1）。短暂失败尚未达到
  重连阈值时仍为 1；合法异常帧证明链路可达，但不代表有新样本。
- `sensor_poll_interval_ms`：当前配置的轮询周期，实际周期可能受读取耗时影响。
- `sensor_sample_age_ms`：距离最近完整成功采集的时间；从未成功时返回 `-ENODATA`。

启动、请求超时、切换等待、退避和轮询休眠都可以被停止流程唤醒。core 卸载时先
关闭请求模块，拒绝新请求并唤醒在途请求，再停止/等待采集线程，最后注销 IIO、
释放接收状态。锁顺序为采集互斥量 → 协议总线锁 → 请求锁；接收回调不获取采集锁。
IIO 发布另持 `indio_dev->mlock` 同步 buffer 开关；buffer 回调不能反向获取采集锁。
常规轮询、启动和退避休眠不持锁；20 ms 切换稳定等待期间保留采集锁，防止手动
波特率操作打断切换验证，但不持协议总线锁。

## 调整与验证

排查未切换到目标配置时，先确认开发板实际卸载旧模块并加载新的 `.ko`。
复制模块文件不改变已经加载的驱动。初始化日志 `acquisition configuration`
显示设备树解析/回退后的目标速率和采样率索引 6；`sensor matched` 显示匹配到的实际
通信速率。协议日志分别标记 40102 暂存、40110 保存/重启、UART 切换和重启后
验证，采样率读回成功才打印 `sampling configuration verified`。
只有最后的 `sensor online` 表示连接配置成功；特征/交替模式还完成了完整特征读取，
纯原始模式则在配置验证后进入批采集，不读取特征。
波特率切换失败时不会继续设置采样率，不能把目标配置日志当成生效证明。

开发板可用 `dmesg -w | grep -E 'acquisition configuration|sensor matched|baud change|40110|sampling|sensor online|sensor connection failed'`
保留各阶段的结果。源代码检查和模拟测试无法证明板上的配置已生效。

目标波特率、采样率、启动/切换等待、请求超时和退避初值在 `ssf_mems_acquisition.c` 顶部；
调速窗口、阈值周期及失败条件在 `acquisition_policy.h` 和对应 `.c` 中。

运行 `python3 tests/acquisition/run_tests.py` 检查调速边界、读取耗时、结构体填充、
计时回绕、启动/验证、掉线重连、合法异常帧、退避上限、手动改速率、丢应答和退出。
测试使用可控时钟和串口替身，不验证真实 UART 时序或内核线程调度。
# 原始/特征交替采集

默认特征轮询约 5 秒后进入定长批采集窗口；窗口约 5 秒内重复 1024 点完整批次，
窗口到期先收完在途批次，再继续特征轮询。全程保持工作波特率，卸载不恢复默认。
时段属性、固件限制与读取方法见 [定长原始采集说明](../protocol/RAW_CAPTURE.md)。
恢复未确认时离线退避，不继续轮询特征；再次连接先确认上传结束，才能更新配置。

运行中可通过特征 IIO 设备的 `sensor_acquisition_mode` 选择 `raw`、`feature` 或
`alternating`，通过 `sensor_raw_duration_ms` / `sensor_feature_duration_ms` 修改
窗口，范围 100..60000 ms。配置只保存在主机内存，断线重连沿用，卸载后重置。
修改不请求重新连接，不写传感器 Flash；写者等待当前原始窗口收尾后持同一采集锁
更新，唤醒线程重设窗口。两个时长分别修改，避免并发写入互相覆盖。
纯原始模式重复定长窗口，每批仍只读确认通信，不插入特征请求；IIO 消费丢样不
当作链路故障。恢复未确认仍进入离线门禁，不会因为选择纯原始而绕过安全检查。
完整 ABI、等待语义和命令见 [IIO 控制说明](../iio/README.md#运行中修改采集策略)。

## 状态读取和模块边界

采集线程按连接、窗口采集、错误处理和下一轮等待拆成独立函数。
`acquisition.lock` 继续保护完整串口事务和配置修改，避免在途批次被打断。
`status_lock` 只保护在线标志、样本时间和生效周期；不跨越串口等待或 IIO 推送。
锁顺序为采集锁到状态锁，状态读取只取状态锁，不反向获取采集锁。
固件升级同样在短临界区清除在线/样本标志。

传输时间和帧间隔统一使用 `serial_transport`；默认采样率及其 Hz 文本从型号表读取。
IIO 属性的完整用户说明见 [ATTRIBUTES.md](../iio/ATTRIBUTES.md)。
